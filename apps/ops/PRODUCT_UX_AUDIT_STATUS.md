# Product UX audit follow-up · October 22, 2026

Source: `spot_orders_product_ux_audit_2026-10-22.md`, supplied by the user. Recommendations were checked against the source and available API fields. Snapshot observations are not treated as permanent counts or new backend contracts.

## Implemented

- **Current operational scope:** open-order queues, partner execution views, active review signals and worker exposure use all available placement history by default. A separate Open-order scope control allows the reporting placement period and reports how many active orders it excludes. Historical placement reporting keeps its original scope. Both modes derive from the shared complete history cache.
- **Attention definitions:** global and trading-app summaries share the active-order checks and deduplicate affected orders. Terminal failures remain a separately named, reporting-period cohort. Age alone does not establish an execution failure.
- **Error consistency:** details read readable reasons from `chunk.description`, `extraTitleTranslated`, `extraTitle` and metadata fallbacks. Differing cached list observations remain accessible with retrieval/source context. No per-order history fan-out was added.
- **Lifecycle evidence:** recognized structured disagreements and Failed records with expiry/cancellation descriptions appear in Data checks and order details. Free text is only an advisory review cue; it never silently changes the shared status classification or totals. Pending + ERROR display state remains an active execution-attempt error.
- **Order readability:** formatted token quantities retain full precision on demand. Execution amounts use reported successful-chunk input amounts only when they are complete and unambiguous. Missing amounts remain unavailable. Due time, deadline, retry eligibility, price-check time and reported execution time have distinct labels.
- **Overview reporting:** orders placed, known placed USD and apps with orders compare the last 7/30 days with the immediately preceding equal rolling window from the same snapshot. Boundary records are counted once; future placements are excluded from bounded reporting totals. Dates, UTC time basis, missing-price coverage and unknown source retention are explained beside the report.
- **Comparison workspace:** Business, Operations and All outcomes column presets; compact/comfortable density; app/network grouping retained; comparisons use the table. Aggregated CSV/JSON exports include the displayed searched/sorted rows, snapshot, scope, grouping, dates, timezone and definitions. No-order visibility avoids calling integrations inactive.
- **Overview hierarchy:** placement reporting and trading-app comparison precede operational diagnostics. Detailed service coverage and pulse are expandable and mount when opened.
- **Analytics:** Trends/Breakdown tabs with metric, breakdown and interval selects replace nested chart tabs. UTC bucket/range labels identify incomplete calendar buckets. “Results” is now “Order outcomes”. The existing placement-time semantics remain explicit.
- **Metadata and wording:** Robinhood Chain (4663) is a display identity without adding fabricated RPC support; unknown token metadata has an explicit state and copyable chain/address identity. Security checks say “No issues detected in this snapshot”. Trading-app network coverage distinguishes networks with orders from configured/historically observed networks.
